VaultChain API Specification

MVP Roadmap and API Inventory

Base URL

    /api

Frontend Default API Base

    http://localhost:3000/api

========================================
Sprint 1 - Authentication & Foundation
========================================

System

GET /api/health
- Health check endpoint.
- Status: implemented

Authentication

POST /api/auth/register
- Create a new user account.
- Create user
- Create wallet
- Return JWT
- Status: implemented

POST /api/auth/login
- Authenticate user.
- Verify credentials
- Return JWT
- Status: implemented

GET /api/auth/me
- Return currently authenticated user.
- Status: planned

Dashboard

GET /api/dashboard/summary
- Return dashboard summary.
- Example values:
  - Total Assets
  - Verification Reports
  - Vault Items
  - Wallet Balance
- Status: planned

========================================
Sprint 2 - Digital Asset Authentication
========================================

Assets

POST /api/assets/upload
- Upload an image.
- Automatically:
  - Store file
  - Generate SHA-256
  - Generate pHash
  - Extract metadata
  - Save asset
- Status: planned

GET /api/assets
- List authenticated user's assets.
- Status: planned

GET /api/assets/:id
- Return asset details.
- Status: planned

DELETE /api/assets/:id
- Delete asset.
- Status: planned

GET /api/assets/:id/hash
- Return SHA-256 and pHash.
- Status: planned

GET /api/assets/:id/metadata
- Return extracted metadata.
- Status: planned

Verification

POST /api/verification/assets/:id
- Verify an asset.
- Checks:
  - SHA-256 duplicate
  - pHash similarity
  - Metadata comparison
- Possible results:
  - Original
  - Duplicate
  - Modified Copy
  - Unknown
- Status: planned

GET /api/verification/reports/:id
- Return verification report.
- Status: planned

========================================
Sprint 4 - Blockchain, Marketplace & Ownership
========================================

Blockchain

POST /api/blockchain/mine
- Deliberately not exposed. Blocks are mined inside the transaction
  that changes ownership, so the ledger always describes something
  that actually happened.
- Status: intentionally omitted

GET /api/blockchain/blocks
- Return blockchain ledger.
- Status: implemented

GET /api/blockchain/assets/:assetId
- Return blockchain history of an asset.
- Status: implemented

GET /api/blockchain/verify
- Re-check every block hash and its link to the previous block.
- Status: implemented

Ownership

POST /api/ownership/transfer
- Deliberately not exposed. Ownership moves only as part of a
  marketplace settlement, so that an ownership change cannot happen
  without the matching payment.
- Status: intentionally omitted

GET /api/ownership/history/:assetId
- Return ownership timeline.
- Status: implemented

Marketplace

GET /api/marketplace/listings
- List active marketplace listings.
- Supports search, minPrice, maxPrice, category, sort, page, limit.
- Returns a pagination block.
- Status: implemented

POST /api/marketplace/listings
- Create marketplace listing.
- Fixed-price sale only. Requires ownership, a passing (or absent)
  verification result, and no existing active listing for the asset.
- Status: implemented

GET /api/marketplace/listings/:id
- Listing details with verification result, hashes, metadata,
  ownership timeline and ledger blocks.
- Status: implemented

GET /api/marketplace/listings/mine
- Caller's own listings in every status.
- Status: implemented

PATCH /api/marketplace/listings/:id
- Update listing price. Seller only, active listings only.
- Cannot set status to sold; only a purchase does that.
- Status: implemented

DELETE /api/marketplace/listings/:id
- Remove listing (soft delete, status becomes removed).
- Status: implemented

POST /api/marketplace/listings/:id/buy
- Buy a listed asset with wallet balance.
- Atomically: debit buyer, credit seller, transfer ownership,
  write ownership history, mine a block, mark the listing sold.
- Status: implemented

GET /api/marketplace/listable-assets
- Caller's assets, each with a listable flag and a reason when blocked.
- Status: implemented

GET /api/marketplace/trades
- Caller's completed purchases and sales.
- Status: implemented

Fractional Ownership

POST /api/fractional/create
- Create fractional ownership.
- Status: planned

GET /api/fractional/:assetId
- Return ownership shares.
- Status: planned

Wallet

GET /api/wallet
- Return wallet summary.
- Status: implemented

GET /api/wallet/transactions
- Return wallet transaction history.
- Status: implemented

POST /api/wallet/transactions
- Add a deposit or withdrawal.
- purchase and sale are rejected here: they are written by the
  marketplace settlement when a trade completes.
- Status: implemented

========================================
Sprint Summary
========================================

Sprint 1: Authentication, JWT, Protected Routes, Dashboard Summary
Sprint 2: Image Upload, SHA-256, pHash, Metadata Extraction, Duplicate Detection, Verification Reports
Sprint 3: OCR, Document Verification, AES-256 Secure Vault
Sprint 4: Blockchain Ledger, Ownership Transfer, Marketplace, Fractional Ownership, Wallet Integration, Final UI Polish

Notes

- Sprint 1 (auth, health, dashboard) and Sprint 2 (upload, hashing, metadata)
  are implemented, along with the Sprint 4 Marketplace, Ownership, Blockchain
  and Wallet endpoints.
- Still outstanding: verification reports, documents and OCR, the encrypted
  vault, and fractional ownership.
- Two endpoints in this file are intentionally omitted rather than pending:
  POST /api/ownership/transfer and POST /api/blockchain/mine. Both would let a
  client change ownership or write ledger history without the payment that is
  supposed to cause it.
- This file is intended as the canonical API checklist for current and future work.
